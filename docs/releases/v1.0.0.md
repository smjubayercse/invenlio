# Invenlio V1.0.0 release scope

V1 implements multi-tenancy and RBAC, product/SKU catalog, warehouse topology, immutable inventory ledger and balances, lot/serial identities, reservations, supplier master data, purchase orders, receiving and put-away, customers and sales orders, allocation, picking, packing, and shipment dispatch. A Java/Spring modular monolith uses PostgreSQL/Flyway and Keycloak; React/TypeScript supplies the desktop browser client.

The local/demo deployment assumes Docker Compose, PostgreSQL 17, Keycloak 26, Java 21, and a modern desktop browser. It is not an Internet-facing production manifest. TLS, managed secrets, hardened identity, monitoring, and backup retention are deployment responsibilities.

V1 does **not** include automated carrier integration, returns/RMA, accounting or invoicing, a VAT engine, SaaS billing, a mobile scanner, advanced WMS optimization, multi-warehouse sales fulfillment, or advanced analytics. These are deferred, not stubbed as finished features.

Release verification (2026-09-24): the real Keycloak/Chromium browser suite passed all 3 scenarios, including login/logout, read-only authorization, and the complete product-to-dispatched-shipment workflow. A disposable, freshly imported Keycloak realm also passed the documented password-free demo bootstrap. The SERIAL PostgreSQL integration flow passed from receipt to dispatch, retaining ledger history with no positive serial on-hand. Java 21 backend verification passed 148 tests across 20 suites with no failures, errors, or skips. Frontend locked install, format, lint, typecheck, 19 tests, and production build passed. A fresh PostgreSQL schema applied and validated Flyway V1–V13, and Hibernate schema validation passed. The Docker backend and static frontend images built. A local backup restored to a separate database with matching products (19), customers (8), sales orders (8), shipments (3), and ledger entries (41); an isolated backend validated the restored schema. Container recreation retained all 3 shipments. Browser E2E found no fatal console errors, uncaught exceptions, critical resource failures, or unexpected 5xx responses.

Inventory reconciliation of the local demo found zero ledger/balance mismatches and zero reserved-projection mismatches. Three active reservations remain from deliberately incomplete prior demo runs; all active sales allocations link to either active or consumed reservations, not released/expired ones. A disposable restored database seeded with 500 extra products served a representative tenant/status page query in about 0.4 ms and count in about 0.2 ms at PostgreSQL level; this is a smoke test, not a production benchmark. No new index was justified at that size.

The frontend dependency audit has no high/critical findings after patching Vite and Vitest. Two moderate and one low advisory remain in development-only test/build tooling; they are not bundled into the Nginx runtime image. A backend CVE feed audit has not been completed and remains a release risk to review in deployment. The local Compose stack and development-mode Keycloak must not be exposed to the Internet. The production Spring profile requires explicit database/OIDC configuration, but TLS, ingress CSP/HSTS, managed secrets, encrypted backup retention, and external monitoring remain operator responsibilities.
