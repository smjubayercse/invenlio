# Invenlio V1.0.1

Patch release candidate for the independently engineered V1 portfolio project. This follows the immutable historical `v1.0.0` tag; it adds no business capability and is not a claim of external production deployment.

## Highlights

- Recruiter-oriented README with a real application hero capture, seven additional workflow captures, engineering invariants, architecture and product-flow diagrams, and a direct local evaluation path.
- Maven and frontend package versions aligned to `1.0.1`; locked pnpm dependency graph remains unchanged.
- CI action references refreshed; the Maven wrapper remains tracked as executable for Linux runners.
- The post-V1.0.0 CI wrapper/path correction is included on the branch; no historical tag was moved.

## Architecture

Java 21 / Spring Boot / Spring Modulith remains one transactional deployable with PostgreSQL as the inventory authority. React/TypeScript uses OIDC/PKCE through Keycloak and a versioned API. Flyway remains forward-only. Redis and Kafka are not required for the synchronous V1 workflow.

## V1 workflow

The authenticated browser test creates catalog and warehouse master data, then proceeds from supplier mapping and purchase order through receiving, put-away, stock, sales allocation, picking, packing, dispatch and a completed order. Read-only authorization and sign-out are separate browser scenarios. Screenshots are captured from that real local flow with synthetic data.

## Verification

- Java 21 `mvnw verify`: **149 backend tests**, zero failures/errors/skips, including PostgreSQL/Testcontainers, migration, authorization, concurrency, Spring Modulith and ArchUnit checks.
- Locked pnpm install, Prettier, ESLint, TypeScript, **19 frontend tests** and Vite production build passed.
- Authenticated Playwright/Chromium: **3 scenarios** passed against local Keycloak, backend and PostgreSQL. The screenshot-enabled workflow passed separately.
- Docker Compose configuration and backend/web image builds passed; the live four-service demo stack reported healthy.

These results describe local verification at the patch-release commit, not GitHub CI status before this commit is pushed. The real badges in the root README link to GitHub workflow status.

## Known limitations

The local Compose stack and development-mode Keycloak are loopback-only evaluation assets, not Internet-facing production manifests. A production deployment requires TLS, managed secrets, hardened identity, monitoring, retention/encrypted backups and a separate backend vulnerability-feed review. The frontend's V1 data selectors and receipt/package creation remain intentionally compact; see `web/README.md`. The patch review's `pnpm audit` reports **two moderate and one low** advisory in development-only tooling (Vitest and its mocker for the moderate findings), with no high/critical frontend finding. It should be rechecked before a deployment; a disruptive major test-tool upgrade is outside this presentation patch. No license has been selected by the owner.

## V2 roadmap, not implemented

Returns/RMA, billing and VAT, carrier integrations, mobile scanning, advanced WMS optimization and analytics remain outside V1. Their inclusion here is not a feature claim.
